## Важные решения

- **Supabase:** в конце этапа 3 создать новый бесплатный проект `veritas-tasks` в регионе Франкфурт (eu-central-1) через подключённый коннектор. Существующие проекты владельца **«VeritasBio» и «Minorq5's Project» не трогать никогда** (ни менять, ни удалять, ни восстанавливать).
- **Почта:** своего домена нет → Gmail SMTP с паролем приложения.
- **Vercel:** владелец подключает репозиторий сам по инструкции (из моего окружения vercel.com недоступен). После каждого этапа — обновлённый сайт и ссылка.
- **XP:** если задачу удалили или вернули в работу в течение 5 минут после выполнения, XP отзывается; после 5 минут закрепляется.
- **Синхронизация:** тестировать особенно жёстко (раздел 19 плана): ни потерь, ни дублей.
- **Язык в адресе** (`/ru`, `/en`, `/bg`) — страницы статические, быстрые, готовы к офлайну.
- **Звуки** — синтез Web Audio (без Howler/Tone.js).
- **CSP** разрешает встроенные скрипты Next.js (`'unsafe-inline'`), потому что у статических страниц не может быть одноразовых nonce; всё остальное закрыто.
- **Playwright закреплён на 1.56.1** — под установленный в окружении Chromium 141 (`/opt/pw-browsers`).
- **Правило пароля:** минимум 8 символов, буквы (любого алфавита) и цифры. На сервере Supabase стоит только длина 8 **без** требования «буквы и цифры», потому что сервер считает буквами только латиницу и отклонил бы пароль «кириллица123». Буквы и цифры проверяет приложение. При настройке облачного проекта: *Authentication → Providers → Email → Minimum password length = 8, Password requirements = No required characters*.
- **Настройки облачного Auth (этап 3):** подтверждение почты — включено, безопасная смена пароля — включена, повторная отправка письма — не чаще 60 с, Site URL — адрес сайта на Vercel, Redirect URLs — `<адрес>/**`; шаблоны писем — из `supabase/templates` (тексты для вставки — в инструкции этапа 3).
- **Удаление аккаунта** — через функцию `delete-account` с `verify_jwt = false` (проверка токена внутри функции — так работает с новыми ключами Supabase). Секретный ключ живёт только в Supabase, в браузер и на Vercel не попадает.
- **Язык писем** берётся из `user_metadata.locale`; при смене языка в настройках он обновляется и там.
- **Выход на всех устройствах**: другие устройства отключаются, когда истекает их токен (до 1 часа) — так устроен Supabase; в интерфейсе это написано честно.

## Известные проблемы и ограничения

- Из моего окружения недоступны `supabase.co` и `vercel.com` — проверка боевого сайта через внешний сервис скриншотов или владельцем.
- Нет видеокарты: 3D рендерится программно; демо-видео будет записываться покадрово.
- Docker Hub ограничивает скачивание — образы Supabase берутся через зеркало `mirror.gcr.io` (`VT_DOCKER_MIRROR=mirror.gcr.io npm run db:start`).
- Полностраничные скриншоты длиннее ~8000 px в программном рендере «заворачиваются» — скрипт снимает экран за экраном.
- Без видеокарты страницы с размытием рисуются со скоростью 4–6 кадров в секунду — скрипты скриншотов ждут дольше и останавливают CSS-анимации. На настоящих устройствах этого нет; производительность на слабых телефонах — отдельная проверка на этапе 12.
- Функции Supabase в локальном стеке подхватываются только при запуске: после добавления новой функции — `npx supabase stop` и снова `npm run db:start` (данные сохраняются).
- QR-код в профиле ведёт на `/add/VT-XXXXX` — эта страница появится на этапе 5 (до этого — «страница не найдена»).
- Если окружение перезапустилось: `dockerd` поднимается заново, контейнеры Supabase стартуют сами, кроме `supabase_edge_runtime_veritas-tasks` — его нужно запустить `docker start supabase_edge_runtime_veritas-tasks` (иначе функции отвечают 502/503).

## Как продолжить в новой сессии

```bash
npm install
# Docker + локальный Supabase (в песочнице без доступа к Docker Hub — через зеркало)
VT_DOCKER_MIRROR=mirror.gcr.io npm run db:start
# .env.local для локальной разработки (ключи — стандартные ключи локального Supabase):
#   NEXT_PUBLIC_SITE_URL=http://localhost:3000
#   NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
#   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<PUBLISHABLE_KEY из `npx supabase status`>
#   SUPABASE_SECRET_KEY=<SECRET_KEY из `npx supabase status`>
npm run dev            # http://localhost:3000/ru, витрина: /ru/design
npm run check          # линтер + типы + юнит-тесты
npm run test:db        # тесты базы (pgTAP)
npm run test:e2e       # e2e на ПК и телефоне (нужны запущенные db:start и dev)
npx tsx scripts/screenshots.ts --routes /ru,/ru/design --out review/stage-N/round-1 --full
npm run shots:stage2 -- review/stage-2/latest   # экраны этапа 2 под демо-аккаунтом
```

Проверка перед каждым коммитом этапа: `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:db`, `npm run test:e2e`, `npm run build`.

Письма в локальной разработке никуда не уходят — их видно в тестовом ящике http://127.0.0.1:54324.
